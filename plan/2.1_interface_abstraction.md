# Task 2.1: Interface Abstraction (TAP)

## Description
Refactor `tap.py` into a proper abstraction layer within the `p2pvpn_daemon` package.

## Requirements
- **Base Interface**: Create `packages/p2pvpn_daemon/p2pvpn_daemon/interface/base.py` with an `abc.ABC` class `BaseTAPInterface` defining `setup`, `teardown`, `write`, and `start_reading`.
- **Implementations**:
    - Move Linux logic to `packages/p2pvpn_daemon/p2pvpn_daemon/interface/linux_tap.py`.
    - Move Windows logic to `packages/p2pvpn_daemon/p2pvpn_daemon/interface/windows_tap.py`.
- **Factory**: Move the `TAPDevice` factory to `packages/p2pvpn_daemon/p2pvpn_daemon/interface/factory.py`.
- **Utilities**: Move `is_admin` and `MAX_FRAME` to `packages/p2pvpn_daemon/p2pvpn_daemon/utils/system.py`.
- **Shim Strategy**: Keep the root `tap.py` as a thin wrapper (shim) that imports from the new `p2pvpn_daemon` package to prevent breaking existing imports in `vpn_node.py` and `main.py`.

## Success Criteria
- All TAP logic is modular and follows the `BaseTAPInterface` contract.
- `tap.py` (shim) still provides the same `TAPDevice` interface to the rest of the project.
- No regression in TAP functionality on Linux or Windows.
