# Task 2.3: Peer Manager Separation

## Description
Extract the peer management logic from `vpn_node.py` into a dedicated `PeerManager` class and formally rename the main engine class to reflect its new role.

## Requirements
- **Rename Requirement**: Rename the main logic class from `VPNNode` to `VPNEngine` (and the file `vpn_node.py` to `engine.py` within the daemon package).
- **Peer Model**: Use the `Peer` model from `p2pvpn_common.models.peer`.
- **Functionality**: Implement `PeerManager` to handle:
    - Adding/removing peers.
    - Updating peer 'last seen' timestamps (`touch`).
    - Determining peer status (alive, pending, dead) using two thresholds: `STALE_TIMEOUT` and `DEAD_TIMEOUT`.
- **Dependency Injection**: Pass the thresholds into the `PeerManager` constructor via a `PeerManagerConfig` dataclass.
- **Logic Refinement**: Refactor the existing peer-tracking logic from `vpn_node.py` to adopt the new two-threshold model.
- **Integration**: The `VPNEngine` will use this `PeerManager` via DI.
- **Testing**: Move/create unit tests for `PeerManager` in `packages/p2pvpn_daemon/tests/core/test_peer_manager.py`.

## Success Criteria
- Peer management is isolated from networking/IO.
- `VPNEngine` is cleaner and relies on `PeerManager` for peer state.
- Unit tests verify the two-threshold lifecycle logic.
- No regression in peer discovery/timeout behavior.
