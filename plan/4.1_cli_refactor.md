# Task 4.1: CLI Refactor

## Description
Refactor `p2pvpn_cli` into a clean, standalone package in `packages/p2pvpn_cli/` that acts as an IPC client for the daemon.

## Requirements
- **Packaging**: Include a `pyproject.toml` for standalone package support.
- **Dependencies**: 
    - Must depend on `p2pvpn_common` for IPC models/protocol.
    - **Layering**: Must have zero knowledge of the VPN's internal Ethernet/encapsulation protocol.
- **Connection Logic**:
    - **Linux**: Unix Domain Socket at `/tmp/p2pvpn.sock`.
    - **Windows**: Localhost TCP loopback on port `5678`.
- **Commands**:
    - `status`: Calls `GET_STATUS`, displays peer table/interface info.
    - `add-peer <host>:<port>`: Calls `ADD_PEER`.
    - `stop`: Calls `STOP`.
- **Robustness**:
    - Exit code `1` for unreachable daemon or IPC error.
    - Readable error messages for all failure modes.
- **Testing**: Integration tests for end-to-end command/response/parsing using a dummy IPC server.

## Success Criteria
- CLI is a thin, decoupled consumer of the IPC service.
- `uv` or `pip` can install it as a package.
- All commands work correctly across Linux and Windows via the abstraction.
