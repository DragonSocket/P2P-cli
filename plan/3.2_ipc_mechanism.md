# Task 3.2: IPC Mechanism

## Description
Implement a lightweight IPC (Inter-Process Communication) server in `packages/p2pvpn_daemon/p2pvpn_daemon/ipc/server.py` that allows the `p2pvpn_cli` to communicate with the `p2pvpn_daemon`.

## Requirements
- **IPC Server**: Implement an asynchronous server listening on a local socket (Unix Domain Socket at `/tmp/p2pvpn.sock` on Linux; localhost TCP loopback on port `5678` on Windows).
  - **Connection Lifecycle**: Use a **connection-per-request** model (Accept $\rightarrow$ Process $\rightarrow$ Respond $\rightarrow$ Close).
- **Command Controller**: Implement an `IPCController` in `packages/p2pvpn_daemon/p2pvpn_daemon/ipc/controller.py` to bridge the server and the `VPNEngine`.
- **Engine API Integration**: The `IPCController` must import `VPNEngine` from `packages.p2pvpn_daemon.p2pvpn_daemon.core.engine` and call:
    - `engine.get_status() -> dict`
    - `engine.add_peer(peer_info: dict) -> bool`
    - `engine.stop() -> None`
- **Protocol Definition**: Follow a local JSON-based protocol:
    - **Request**: `{"command": "COMMAND_NAME", "params": {...}}`
    - **Response**: `{"status": "success", "data": {...}}` OR `{"status": "error", "message": "..."}`
- **Robustness**: Handle malformed JSON and unknown commands with appropriate error responses.
- **Testing**: 
    - **Unit Tests**: `pytest` for `IPCController` with mocked `VPNEngine`.
    - **Integration Tests**: `pytest` for the IPC server using a mock client.
- **Lifecycle**: Ensure the `IPCServer` closes the socket listener gracefully upon receiving a shutdown signal from the `VPNEngine`.

## Success Criteria
- The daemon responds to CLI commands via IPC.
- The JSON protocol is strictly followed.
- Errors are reported through the JSON response, not just logs.
- All tests pass.
