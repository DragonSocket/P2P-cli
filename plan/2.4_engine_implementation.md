# Task 2.4: Engine Implementation (DI Integration)

## Description
Rebuild the `VPNEngine` (formerly `VPNNode`) in `packages/p2pvpn_daemon/p2pvpn_daemon/core/engine.py` using Dependency Injection.

## Requirements
- **Constructor**: `VPNEngine(tap_interface: BaseTAPInterface, transport: BaseUDPTransport, peer_manager: PeerManager, config: VPNConfig)`.
- **Concurrency Model**: Use **`asyncio`** with a **callback-based pattern** (e.g., `tap_interface.register_callback(self.on_tap_frame)`).
- **Orchestration (Core Loop)**: Implement a `run()` method that:
    - Gracefully `setup`s the TAP and PeerManager.
    - Starts the UDP Transport.
    - Manages task lifecycles (e.g., using a `TaskGroup` or `asyncio.gather`) to ensure all concurrent operations are cancellable.
    - **Inbound Flow**: `on_udp_packet` $\rightarrow$ validate peer in `PeerManager` $\rightarrow$ `tap_interface.write`.
    - **Outbound Flow**: `on_tap_frame` $\rightarrow$ extract destination IP from frame $\rightarrow$ resolve peer in `PeerManager` $\rightarrow$ `transport.sendto`.
- **Lifecycle & Error Handling**:
    - Implement a `shutdown()` method for clean termination (closing TAP, stopping transport, and canceling all tasks).
    - Handle component failures during the `setup` phase.
- **Testing**: Write integration tests using `MockTAPInterface` and `MockUDPTransport` in `packages/p2pvpn_daemon/tests/core/test_engine.py` to verify full orchestration and graceful shutdown.

## Success Criteria
- `VPNEngine` is a clean orchestrator that does not manage its own I/O or peer state directly.
- The engine handles the full packet lifecycle correctly.
- Graceful shutdown works without resource leaks.
- Integration tests pass with mocks.
