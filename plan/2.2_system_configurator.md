# Task 2.2: System Configurator Decoupling

## Description
Decouple system-level configuration commands from the TAP interface I/O to allow for testing and better modularity.

## Requirements
- **Abstraction**: Create `BaseSystemConfigurator` (ABC) in `packages/p2pvpn_daemon/p2pvpn_daemon/interface/base.py`.
- **Implementations**:
    - `LinuxSystemConfigurator` in `packages/p2pvpn_daemon/p2pvpn_daemon/interface/linux_configurator.py`.
    - `WindowsSystemConfigurator` in `packages/p2pvpn_daemon/p2pvpn_daemon/interface/windows_configurator.py`.
- **Migration**: Move all `os.system`, `subprocess`, `netsh`, `iptables`, `ethtool`, and PowerShell calls from the original `tap.py` into these new configurator classes.
- **Dependency Injection**: Refactor the `TAPInterface` implementations to receive a `BaseSystemConfigurator` instance via their constructor.
- **Testing**: Ensure `TAPInterface` can be unit-tested using a `MockSystemConfigurator` to verify command execution without affecting the host system.

## Success Criteria
- The interface logic is completely separated from the system configuration logic.
- `TAPInterface` can be tested in isolation with mocked system calls.
- No breaking changes in the current (shimmed) `tap.py` interface.
