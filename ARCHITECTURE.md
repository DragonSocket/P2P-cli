# Архитектура v2

Один устанавливаемый пакет вместо трёх взаимозависимых дистрибутивов.
Границы MVC выражены зависимостями, а не количеством пакетов.

| Слой | Модули | Ответственность |
|---|---|---|
| Model | models, peers, routing, engine | конфиг, членство, MAC-таблица, сценарии ядра |
| Controller | controller | команды управления и валидация параметров |
| View | cli, views | аргументы, JSON, таблица, монитор |
| Порты | contracts | Link, Transport, Discovery |
| Адаптеры | adapters, discovery, protocol, ipc | Linux TAP, UDP, Kademlia, AEAD, Unix socket |
| Сборка | daemon | выбор реализаций, сигналы, логи, lifecycle |

`Engine` получает зависимости через конструктор. `LinuxConfigurator` отдельно
от I/O TAP. Таблица пиров отдельно от маршрутизации и кодека. CLI импортирует
сборку демона только для `run`; управляющие команды работают через IPC.
Логирование конфигурируется только в точке сборки, не при импорте библиотеки.

Поток данных: приложение → маршрут виртуальной подсети → TAP → learning switch
→ AEAD → UDP → AEAD/проверка членства → TAP → приложение. Полученные сетевые
кадры не ретранслируются обратно в mesh; broadcast не образует циклов.

Поток обнаружения: seed DHT → публикация короткоживущей записи → поиск имени
→ HELLO к endpoint → подтверждение/наблюдаемый endpoint → обмен именами соседей
→ периодический поиск новых соседей. Kademlia RPC также зашифрованы и принимаются
только участниками роя. DHT и data используют отдельные ключевые домены/порты.

Поток управления: CLI → приватный Unix socket → Controller → Engine.
Ключ роя никогда не возвращается через status. Сокет 0600, каталог принадлежит
процессу и не доступен на запись группе/остальным; lock защищает единственный
экземпляр. SIGTERM/stop закрывают IPC, задачи, TAP и UDP. При ошибке фоновой
задачи сервис завершается с ошибкой, systemd выполняет рестарт.

Безопасность и пределы: общий ключ удостоверяет членство, не личность.
Записи не являются глобальным DNS. Доверенная группа может подделать имя.
Репликация DHT не гарантирует достижимость транспорта; NAT traversal/relay —
отдельный незавершённый этап. Полный список ограничений и проверок — в README.
